Browser And Code

Browser automation works, but the presenter warns that it can burn context quickly

Hermes can connect to a browser through Chrome DevTools Protocol. The demo opens a Google Form in a logged-in browser, connects Hermes to the browser, then asks it to fill fields without submitting. The presenter notes this is powerful, but browser snapshots and visual context can consume many tokens.

Cost And Caution

The demo cost is low, but token management still matters

At the end, the presenter says the full demo cost about one US dollar using a DeepSeek model through OpenRouter. The run included research, Telegram gateway use, browser control, coding, and cron/memory experiments. He reports around 58 requests and about 1.74 million tokens.

  • Cheap models make personal-agent experiments much easier, but long context can still make each request expensive.
  • Browser automation should be used selectively because it can inflate token usage and context size.
  • Agent workflows should support model profiles: cheap, fast, strong, UI-capable, code-capable, and review-focused models.
  • Security prompts should be read carefully. Do not approve everything blindly just because the tool asks often.
  • Even if an action was approved before, important files and sensitive operations should still trigger fresh review.
Platform Takeaways

What this means for your agentic AI platform

This video is useful for your BA-facing platform because Hermes shows the pieces a real personal agent needs: secure tool access, memory, scheduled tasks, gateways, observability, plugin surfaces, and explicit approvals.

  • Agent runtime is more than prompts. Your Master Agent/Sub-Agent model should include memory store, scheduler, gateway, tool permissions, logs, and recovery controls.
  • Separate tool permission levels. BA users should understand read-only, write, local-file, network, browser, messaging, and scheduled-action permissions.
  • Make secret handling explicit. Actionable Skills should declare which secrets are injected, where they are stored, whether they are readable, and how they are redacted in traces.
  • Use deterministic infrastructure for schedules. A cron-style scheduler is easier to inspect than a pure LLM heartbeat. Flow Markdown should support scheduled triggers.
  • Memory needs curation, not just storage. Add rules for deduplication, promotion, expiry, source linkage, and when a memory becomes a reusable skill.
  • Gateways change the product shape. Telegram, Line, Slack, email, and webchat are not just channels; they are remote-control surfaces for the agent.
  • Approvals need good UX. Allow once, allow for session, always allow, deny, explain command, and stop current run should be built into the platform.
  • Browser control is expensive and risky. Prefer APIs and typed tools. Use browser automation only when the workflow truly depends on human UI state.
  • Cost observability is a product feature. Show requests, tokens, model, estimated cost, and context growth per task.
  • Support model profiles. Let BA-authored flows specify model intent: cheap routine agent, high-reasoning agent, UI builder, code reviewer, or compliance checker.
