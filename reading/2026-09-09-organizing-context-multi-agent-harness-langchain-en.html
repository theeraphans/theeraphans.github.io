Organizing Context in a Multi-Agent Harness

Subagents do not all need the same context. LangChain's new context modes make the choice explicit: inherit the supervisor's working history when continuity matters, or start fresh when focus and independent judgment matter more.

LangChain OSS · Thushanth Bengre and Chester Curme6-minute readPublished September 8, 2026Summary run September 9, 2026 · 18:23 ICT

This article summarizes the supplied one-page PDF capture and checks it against LangChain's original post. Product behavior refers to the September 2026 Deep Agents release described by the authors. The implementation guidance and risk analysis below are editorial interpretation.

Executive summary

Context inheritance is a role-design decision

A supervisor-based agent system delegates tasks to subagents to gain parallelism and protect the supervisor's context window from implementation detail. Historically, a subagent commonly started with an empty context and received only a task description. That isolation is useful, but it can waste time when the supervisor has already read files, traced a failure, or established constraints that the worker needs.

Deep Agents now exposes two context modes. An isolated subagent starts fresh with the delegated task. A forked subagent receives the supervisor's conversation and state, minus the trailing delegation tool call, plus a role preamble and task message. When the subagent finishes, only its final response returns to the supervisor.

The correct choice follows the epistemic relationship between parent and child. A worker continuing established work should usually fork. A verifier testing the parent's conclusion should usually remain isolated. Researchers tend toward isolation when their questions stand alone; memory agents tend toward fork because the conversation itself is their source material.

The design rule

Share context when it is reusable evidence. Withhold context when it is a source of anchoring, noise, unnecessary cost, or privilege.

The problem

Fresh context protects focus but repeats discovery

Subagents help a supervisor manage context by hiding intermediate reasoning and returning a condensed outcome. They also let multiple investigations run in parallel. The cost of starting every child from zero is redundant context gathering: repeated file reads, searches, code navigation, and reconstruction of decisions the supervisor has already made.

Passing everything is not automatically better. The full conversation may contain false starts, untrusted input, private data, tool results irrelevant to the child, and conclusions that bias an independent review. Context is both an information asset and an attack surface.

Two context modes

Fork versus Isolated

mode: forkContinue from the supervisor's state

Receives: conversation history and current state, with the delegation call rewritten into a task.

Best for: work that depends on investigation or decisions already made.

Benefit: less rediscovery and better prompt caching.

Risk: inherited assumptions, excess disclosure, and larger context.

mode: isolatedBegin with a focused task

Receives: the task description and explicitly supplied review material.

Best for: independent evaluation and self-contained research.

Benefit: focus, lower anchoring, and controlled disclosure.

Risk: missing evidence and repeated tool calls.

Fork mechanics

How a forked delegation moves through the harness

1 · DelegateSupervisor calls a subagent

The call includes a concrete task description.

2 · RewriteRemove the trailing call

The task becomes a user message beside a fixed role preamble.

3 · ContinueChild inherits state

It works from the supervisor's history and cached prompt prefix.

4 · UnwindReturn one result

The final child message becomes the tool result seen by the supervisor.

Prompt caching matters because a fork can reuse the supervisor's existing prefix rather than paying to rebuild equivalent context through tools. Forking still seeds the child with more tokens; its efficiency depends on whether that inherited history prevents enough repeated work to justify the larger input.

Role patterns

Four agents, four relationships to context

Worker · forkContinue diagnosed work.

A supervisor traces a timeout to retry logic. The fixer inherits that evidence, implements the change, and adds a regression test without re-running the investigation.

Verifier · isolatedEvaluate independently.

A reviewer receives the diff, requirements, and rubric without the supervisor's reasoning, reducing confirmation bias and anchoring.

Researcher · isolatedAnswer a self-contained question.

Parallel researchers each receive a narrow question and dedicated search tools, rather than duplicating an unrelated supervisor history.

Memory agent · forkExtract durable information.

The conversation is the data being analyzed, so the memorizer needs it. File permissions restrict where remembered facts may be written.

These are defaults, not rigid types. A researcher investigating why the current debugging theory fails may need a fork. A worker performing a clean-room reimplementation may need isolation. The task's dependency on prior reasoning is more important than its label.

Decision framework

Ask what the child must know and what it must not inherit

Does the task continue an investigation already completed by the supervisor?Reuse evidence and decisions.Fork
Must the child provide independent judgment?Avoid inheriting the proposed conclusion.Isolated
Is the conversation itself the material to analyze?Preferences, decisions, or interaction history.Fork
Can the question stand alone with a compact evidence packet?Keep parallel research focused.Isolated
Does the supervisor history contain unnecessary secrets or untrusted text?Minimize disclosure and injection propagation.Isolated
Would reconstructing context require expensive repeated tool calls?Exploit continuity and prompt caching.Fork

Implementation model

Context mode is one specialization lever

Deep Agents configures the choice on each subagent definition:

const fixer: SubAgent = {
  mode: "fork",
  name: "fixer",
  description: "Implement and test an already-diagnosed fix",
  systemPrompt: "...",
};

const reviewer: SubAgent = {
  mode: "isolated",
  name: "reviewer",
  description: "Independently review completed work",
  systemPrompt: "...",
};

Mode works alongside tools, middleware, system prompts, permissions, and output contracts. A memory agent in the article inherits context but receives file restrictions: deny writes broadly, then permit only approved documentation paths. This illustrates an important rule: access to conversational context should not imply unrestricted operational authority.

Critical assessment

Continuity, independence, and trust pull in different directions

Fork strengthLess duplicated discovery.

Workers can act on the supervisor's evidence immediately, and cached prefixes may reduce cost.

Fork riskAssumptions propagate faster.

A mistaken diagnosis, injected instruction, or irrelevant private fact enters every forked continuation.

Isolation strengthIndependent judgment is more credible.

A reviewer is less likely to reproduce the author's framing simply because it appeared earlier.

Isolation riskFresh does not mean informed.

The task must include requirements, diff, tests, and relevant evidence or the review becomes shallow.

Operational riskFull history may exceed need-to-know.

Apply data classification and permission checks before propagating state.

Evaluation needMeasure outcomes by role.

Compare task success, repeated reads, tokens, latency, review findings, and correlated failures.

The X reply captured in the supplied PDF raises a useful objection: fork solves context continuity, not context trust. Traceable evidence and verifiable sources still matter. A child that inherits a confident but unsupported conclusion has become faster without becoming more correct.

For a multi-agent platform

Make context policy explicit in every agent contract

  1. Declare the mode per subagent instead of inheriting one global default silently.
  2. Record why the role needs continuity or independence.
  3. For isolated agents, define a minimal evidence packet with requirements, artifacts, and rubrics.
  4. For forked agents, filter secrets, irrelevant history, and untrusted instructions before propagation.
  5. Keep tool permissions separate from context visibility.
  6. Return structured outcomes and evidence rather than the child's full intermediate transcript.
  7. Trace lineage: parent run, fork point, context digest, task, tools, and final result.
  8. Evaluate correlated errors between supervisor and child, especially for forked reviewers.
  9. Measure redundant reads and token cost to verify that forking actually saves work.
  10. Allow a child to request missing context instead of receiving everything preemptively.

Takeaways

Ten ideas worth keeping

  1. Subagents isolate detail from the supervisor and enable parallel work.
  2. Starting every child fresh can repeat expensive context gathering.
  3. Fork passes the supervisor's state and supports prompt caching.
  4. Workers usually benefit from continuity when the diagnosis is already established.
  5. Verifiers usually benefit from isolation to reduce anchoring.
  6. Self-contained researchers should receive focused questions and dedicated tools.
  7. Memory agents need conversation history because it is their source material.
  8. Context access and tool permissions are separate security decisions.
  9. Isolation requires a complete evidence packet; fork requires context filtering.
  10. The right mode depends on the child's relationship to prior reasoning, not its name.
