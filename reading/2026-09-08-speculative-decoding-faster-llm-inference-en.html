Fast Inference from Transformers via Speculative Decoding

Accelerated exact autoregressive sampling by letting a cheap draft propose several tokens and having the target model verify them in parallel without changing its output distribution.

The problem

What was missing before this work

Large-model decoding is sequential: one expensive forward step usually produces one token, even when accelerator arithmetic is underutilized. Batching helps throughput but not single-request dependency depth.

A smaller model can predict likely continuations cheaply, but naively using its tokens changes quality.

Core idea

The paper in one idea

Have a draft model generate a short token block autoregressively. Run the target model once over that block to obtain all target probabilities, then accept matching proposals with a rejection-sampling rule.

If several proposals are accepted, one target pass advances several tokens. A correction distribution on rejection preserves the target model’s sampling distribution.

Accept draft token with min(1, p_target(token)/p_draft(token)); sample correction on rejection.

Mechanism

How the method works

Draft γ tokens, evaluate them with the target in parallel, compare target and draft probabilities token by token, accept the prefix until the first rejection, sample a corrected token, and repeat.

When every proposal is accepted, also sample one additional target token from the final position to maximize progress.

Technical deep dive

The machinery that matters

Correctness is distributional, not merely greedy agreement. The residual distribution is proportional to max(0, p−q) after rejection. Random-number handling and identical sampling settings matter.

Expected speedup grows with acceptance and the ratio between target-pass cost and draft cost. Longer speculation increases potential gain but wastes more work on early rejection.

Evidence

What the experiments established

The companion papers reported multiple-times decoding speedups across translation and language-model workloads while preserving the target distribution.

Results depend on model pair, hardware, batch size, sampling temperature, and implementation. High-throughput serving can have less idle target compute to exploit.

Why it mattered

How it changed the field

Speculation created a broad design space: independent draft models, self-drafting heads, prompt lookup, tree proposals, and systems that adapt γ online.

It reframed small models as latency accelerators rather than only cheaper quality alternatives.

Engineering use

What an AI engineer should do with it

Measure accepted tokens per target pass, draft overhead, time to first token, inter-token latency, and end-to-end throughput. Tune speculation length by workload.

Keep tokenizer and vocabulary aligned or provide a proven mapping. Verify exact sampling with statistical tests, especially after kernel or quantization changes.

Limits and later corrections

Where the result stops

Low acceptance can make the method slower. Domain shift, high temperature, creative tasks, and a weak draft reduce agreement.

Extra model weights consume memory, and correctness guarantees can break through approximate verification or mismatched sampling code.

Takeaways

What to remember

  • A draft proposes multiple future tokens cheaply.
  • The target verifies proposals in one parallel pass.
  • Rejection sampling preserves the target distribution.
  • Acceptance rate determines useful speedup.
  • Draft cost and memory must be included.
  • Statistical correctness tests are essential.
