The problem

What was missing before this work

During autoregressive decoding, the model generates one token at a time and rereads cached keys and values for all previous tokens. Arithmetic per step is small relative to memory movement, so decoding becomes bandwidth-bound.

Ordinary multi-head attention stores separate K and V tensors for every head. The paper asks whether queries need multiple views while keys and values can be shared.

Core idea

The paper in one idea

Keep many learned query projections but replace per-head key and value projections with a single shared pair. Every query head attends to the same cached keys and values through its own query representation.

The KV cache shrinks roughly with the number of key/value heads, reducing bytes read per generated token and allowing larger batches or faster decoding.

Q: H heads; K,V: 1 shared head; KV cache/token ∝ 2dₖ instead of 2Hdₖ

Mechanism

How the method works

Project the current hidden state into multiple query heads. Project each source token once into one key and one value head. Broadcast the shared K and V across query-head attention computations.

At decode time, append only one key/value vector pair per layer and token. Query heads still produce diverse score patterns because their projections differ.

Technical deep dive

The machinery that matters

MQA retains the output shape of multi-head attention and changes only K/V head count. The reduction targets memory bandwidth and cache capacity; training FLOPs do not fall in direct proportion because query and output projections remain.

Checkpoint architecture must agree on KV-head count. Converting an already trained MHA model to MQA is not a simple runtime flag because weight shapes and learned specialization differ.

Evidence

What the experiments established

The paper reported comparable quality to multi-head baselines on translation tasks with much faster incremental decoding. The central system claim is that reduced memory traffic improves latency in the tested serving setup.

Quality parity is task- and scale-dependent. Later work found that full sharing can cost quality for some large models, motivating grouped-query attention.

Why it mattered

How it changed the field

MQA made KV-head count an explicit architecture and serving parameter. It became important as long contexts and high-concurrency inference caused KV cache to dominate accelerator memory.

The design connects model architecture directly to production economics: fewer cached bytes can increase batch size, throughput, and context capacity.

Engineering use

What an AI engineer should do with it

Calculate cache bytes from layers, sequence length, batch, KV heads, head width, dtype, and both K and V. Do not estimate from parameter count alone.

Ensure kernels understand broadcasted KV heads and tensor-parallel sharding. A theoretically smaller cache may fail to improve latency if the kernel introduces expansion or inefficient memory access.

Limits and later corrections

Where the result stops

One shared K/V representation can become an information bottleneck and reduce quality. MQA does not reduce cache growth with sequence length and does not address prefill attention’s quadratic work.

Latency gains depend on decode being bandwidth-bound. Small batches, short contexts, or kernel overhead can change the result.

Connections

Where this paper sits in the learning path

GQA interpolates between MHA and MQA by using several KV groups. PagedAttention later manages the resulting cache blocks across many requests, while KV compression changes precision or token retention.

Takeaways

What to remember

  • MQA preserves multiple query heads but shares keys and values.
  • The primary target is decode-time memory bandwidth.
  • KV cache capacity is an architectural concern.
  • Cache savings can increase serving batch size.
  • Quality may fall when one KV representation is too restrictive.
  • Kernel support determines realized speed.
