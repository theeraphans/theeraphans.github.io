Missing point of view

Correct is not the same as distinctive

Landing pages, portfolios, dashboards, and mobile apps need different design intent, not one universal idea of good.

The practical lesson: a design skill should not only tell the model to "make it beautiful." It should force a concrete direction, constraints, examples, forbidden patterns, and the rules for the target medium.

Functional UI

Functional product UI should lean on component systems, not pure invention.

The video draws a clear distinction between marketing pages and real applications. Marketing pages can be expressive and artistic. Product dashboards and operational tools need consistent, predictable components that people can use repeatedly.

Layer What It Provides Why It Matters
Shadcn skill A rulebook for building with Shadcn conventions and fitting the current project setup. Gives the agent judgment about how to use components correctly.
Shadcn MCP A live connection to the Shadcn registry so the model can browse and pull real components. Connects the agent to professional-grade components instead of hand-building rough versions.
Dashboard skill A layout skill focused on grouping information, density, hierarchy, and screen organization. Dashboards are less about isolated components and more about arranging information coherently.

This is a clean example of skill plus MCP separation: the skill carries rules and reasoning, while the MCP gives live access to components and data.

Platform Takeaways

What this means for your Master Agent, Sub-Agent, Skill, and MCP platform

This video is useful because it gives a concrete taxonomy for skills. Not every skill should be a persona. Some skills define direction, some define component rules, some connect tools, some generate assets, and some verify platform-specific quality.

  • Split skills by job type. Marketing UI, functional app UI, dashboards, animation, visual generation, and mobile should not share one giant design prompt.
  • Model cognitive vs actionable skills. Design direction and taste presets are cognitive. Shadcn MCP, GSAP implementation, Higgsfield asset generation, and Expo builds are actionable.
  • Pair every MCP with a skill. The MCP gives access. The skill tells the agent when, why, and how to use that access correctly.
  • Use decision-first design flows. Before generating UI, force the agent to choose product category, visual direction, component system, motion level, and media strategy.
  • Make forbidden patterns explicit. Store "avoid AI slop" rules such as generic gradients, stock imagery, repeated scroll reveals, and inconsistent typography in skill definitions.
  • Let BAs choose design intent in business language. Instead of asking for CSS details, ask if the experience should be editorial, premium, operational, playful, brutalist, mobile-native, or dashboard-dense.
  • Add verification gates. Check accessibility, responsive layout, component consistency, animation performance, mobile ergonomics, and asset relevance.
  • Version skill packs. The video notes that newer models need updated prompting. Treat design skills as versioned assets tied to model capability.
Flow Markdown

A BA-friendly design Flow Markdown should select skill layers before code is generated.

The practical artifact for your platform is a reusable UI generation spec. It should let the BA define product type and design intent, then let the platform attach the right skills and tools. 

# Design Flow: Product Website or App UI

goal: Generate a distinctive, production-ready interface for a specific product context.
owner: Design Master Agent
flow_type: skill_layered_ui_generation

input:
  product_type: analytics_dashboard
  audience: operations_team
  primary_goal: repeated daily use
  design_intent: quiet_professional_dense
  platform: web

skill_layers:
  direction:
    skill: front_end_design_direction
    rules:
      - commit_to_visual_direction_before_code
      - avoid_generic_ai_defaults
  component_system:
    skill: shadcn_rules
    mcp_required: shadcn_registry
  layout:
    skill: dashboard_information_architecture
    focus:
      - grouping
      - density
      - hierarchy
      - scanability
  motion:
    skill: gsap_motion
    use_when: marketing_or_storytelling_required
    performance_gate: animate_transform_and_opacity
  assets:
    skill: generated_visual_assets
    use_when: hero_or_background_media_required

platform_rules:
  responsive_breakpoints: [mobile, tablet, desktop]
  accessibility_required: true
  no_text_overflow: true
  no_horizontal_scroll: true

verification:
  - design_direction_matches_product
  - component_usage_matches_project
  - dashboard_density_is_readable
  - animations_are_smooth
  - visuals_are_relevant
  - mobile_layout_is_not_shrunken_desktop

failure_policy:
  on_generic_design: restart_with_stronger_direction
  on_component_mismatch: reload_component_system_rules
  on_mobile_failure: switch_to_mobile_native_skill
  on_asset_mismatch: regenerate_or_remove_media
