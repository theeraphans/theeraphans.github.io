OpenWiki

An Agent for Repo Documentation

A readable summary of LangChain's OpenWiki demo. OpenWiki is an open source agent that generates, updates, and exposes repository documentation designed for coding agents, so agents can understand not only what the code does, but also why important implementation decisions exist.

The Short Version

OpenWiki is a repository documentation agent. You install it with NPM, run an init command, choose a model provider, and it generates an OpenWiki documentation directory for the current repo. It can update those docs from Git history, expose them to coding agents through agents.md or claude.md, and optionally trace runs through LangSmith.

  • OpenWiki creates agent-readable docs that act as both repo overview and navigation map.
  • Docs stay current by inspecting commits, PR descriptions, comments, and file changes since the last update.
  • The agents.md integration tells coding agents when and how to use OpenWiki context automatically.

Setup

OpenWiki starts as a local CLI flow, then immediately generates docs

The demo begins by installing OpenWiki through NPM and running openwiki init. The init process asks for a model provider, API key, and model choice. It supports open and closed model providers, includes predefined models, and lets users provide a custom model ID when needed.

InstallInstall OpenWiki locally through NPM.
InitRun openwiki init inside the target repository.
ProviderSelect a model provider such as OpenRouter or another supported provider.
ModelChoose a predefined model or enter a custom model ID.
TraceOptionally add a LangSmith API key to trace every action.
GenerateOpenWiki starts generating repository documentation.
Documentation Shape

The generated docs are an index and knowledge map for future coding agents

OpenWiki creates an OpenWiki directory with a quickstart.md file and subdirectories for different parts of the repository. The quickstart file is the index: it describes the repo at a high level, names important files, links to deeper docs, and gives a coding agent a fast first stop when it needs repository context.

Quickstart Index

High-level repository overview, important files, and links into the rest of the OpenWiki documentation.

Subsystem Docs

Focused pages for architecture, CLI behavior, operations, agent internals, and other major repo areas.

Decision Context

Business logic and reasoning behind implementation choices, derived from commits, PRs, comments, and history.

The important design choice is that the docs are not only for humans. They are written as context that coding agents should inspect first.

Automation

A GitHub Action can keep OpenWiki docs updated from Git history

OpenWiki is not meant to become another manual documentation chore. The demo shows a GitHub Action that runs openwiki update on a schedule and opens a pull request with documentation updates. The update process uses Git history as its input.

Track

Last checked commit

OpenWiki stores the commit hash that was last reflected in the docs.

Inspect

New changes

It reviews commits, changed files, PR descriptions, comments, and related context after that point.

Propose

Documentation PR

The scheduled action can open a pull request updating the OpenWiki docs when changes are needed.

  • Schedule is flexible. A quiet repo may update weekly, while a high-volume repo may update every few hours.
  • The agent is time-frame independent. It reads Git history, so the schedule can be adjusted without changing the core behavior.
  • Docs become part of review flow. Humans still merge the update PRs, which keeps generated documentation inspectable.
Chat Mode

OpenWiki is also a repo-aware chatbot and docs manager

Running OpenWiki without the init or update command launches a chat interface. From there, the user can customize model settings, update or clear docs, ask questions about the repo, search through generated documentation, and make targeted changes.

Mode User can do Why it matters
Ask Ask questions about the repository or generated docs. OpenWiki becomes a lightweight knowledge interface over the codebase.
Manage Update, clear, or tune documentation behavior. Docs can be maintained without hand-editing every file.
Edit Request targeted changes to specific documentation areas. The generated wiki can evolve with human feedback and repo changes.
Agent Context

agents.md or claude.md tells coding agents to use OpenWiki automatically

The final step is how other coding agents discover OpenWiki. OpenWiki creates or updates agents.md, or claude.md for Claude Code, with instructions that tell the coding agent where the OpenWiki docs live and when to use them. That means future coding agents can pick up repository context without extra prompting.

Platform Takeaways

What this means for your agentic AI platform

OpenWiki is especially relevant to your BA-facing platform because it shows a practical memory/documentation layer for agents. It turns repository understanding into a maintained artifact instead of repeatedly rediscovering the same context.

  • Make agent-readable docs a first-class memory layer. Not all memory should be vectors or chat history; structured markdown can guide agents directly.
  • Use an index file as the entrypoint. A quickstart-style page gives Master Agents and Sub-Agents a predictable first place to inspect.
  • Capture why, not only what. Commit history, PR descriptions, and comments can explain business logic and design decisions that code alone does not reveal.
  • Automate documentation updates through workflow triggers. Scheduled updates or merge-triggered updates can keep Flow Markdown, Skill Cards, and SOP docs fresh.
  • Surface docs through agent instruction files. Your platform can generate agents.md-style guidance that tells agents where to find approved context.
  • Trace documentation agents. LangSmith-style tracing matters because generated docs become part of future agent decisions.
  • Use PRs for governance. Generated documentation should be reviewable, diffable, and mergeable rather than silently changing platform memory.
  • Extend the pattern beyond code repos. The same approach can maintain SOP documentation, business process maps, tool catalogs, policy docs, and agent skill libraries.
