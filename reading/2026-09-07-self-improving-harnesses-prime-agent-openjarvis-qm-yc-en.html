Self-Improving Agent Harnesses: Prime Agent, OpenJarvis, and YC's QM

YC Harness Club argues that the wrapper around a model is becoming an agentic operating system. Three systems show the frontier: persistent recursive agents, cloud-optimized local AI, and a company-wide work agent built around shared context, elastic sandboxes, and guarded tools.

Y Combinator · YC Paper Club 1h 00m Published September 7, 2026 Summary run September 7, 2026 · 22:36 ICT

This editorial summary is based on the complete English transcript. Benchmark and cost figures are reported as presented by the speakers; they are not independently reproduced here.

Executive summary

The harness is no longer “just a wrapper”

The session opens with a challenge to a common dismissal: harness work is merely scaffolding or prompt engineering, and therefore not serious research. The speakers argue the opposite. A model supplies a sequential token processor; the harness supplies persistent state, context construction, tools, execution, memory, sub-agents, budgets, permissions, and the feedback loops that let the same weights tackle longer and more difficult work.

The headline evidence is ARC-AGI. The event reports that a raw model result near 30% can rise to roughly 95% with a stronger harness, with another NVIDIA system reaching 100% on the cited setup. The exact comparison needs careful protocol review, but the broader lesson is credible: evaluating “the model” without fixing the harness, budget, tools, and sandbox can measure an entire system while attributing the result to only one component.

Prime AgentMake the harness maximally expressive.

Persistent recursive sub-agents, programmable context, live state, inter-agent messaging, and refinement across long-running work.

OpenJarvisOwn the personal AI stack locally.

Composable model, inference engine, agent logic, tools, memory, and learning optimized for private, inexpensive on-device execution.

QM at YCMake one work agent useful across a company.

Centralized conversational state, disposable sandboxes, company tools, model choice, Slack collaboration, and human-reviewed writes.

Together, the talks reveal three different bottlenecks. Prime Agent focuses on what an agent can express over time. OpenJarvis focuses on where intelligence runs and who owns it. QM focuses on how an agent participates in organizational work without losing personalization, manageability, or access control.

The central design principle

A capable agent is not a prompt plus a tool list. It is a governed runtime that decides what context to load, what computation to perform, what state to retain, which environment to use, how long to continue, and when a human must intervene.

Harness evolution

From a token loop to a self-modifying runtime

2019 · GPT-2Generate until stop

The earliest harness is little more than a prompt, sampling policy, environment, and an end-of-sequence loop. The model cannot call tools, edit memory, or delegate.

2020 onwardContext becomes a control surface

Few-shot examples teach behavior in context. Chain-of-thought expands the output space so intermediate reasoning can consume test-time compute before producing an answer.

ToolsAct outside the weights

WebGPT and Toolformer-style interfaces let the model emit structured calls to calculators, search, code, and external APIs. The harness executes the call and returns observations.

MemoryEdit context over time

MemGPT-style systems introduce create, read, update, and delete operations over memory instead of append-only conversation. Context management becomes an active process.

SkillsPersist successful procedures

Voyager demonstrates how useful tool sequences can be distilled into reusable instructions or programs. A successful trajectory becomes capability available to later tasks.

ReflectionUse feedback to revise

ReAct, Self-Refine, and Reflexion establish loops where actions receive environmental or evaluator feedback, then the agent attempts a correction.

Multi-agent and RLMDelegate recursively

Sub-agents isolate contexts and parallelize work. Recursive language models expose a programmable query primitive so agents can call further agents as part of computation.

Self-improvingEdit prompt, memory, skills, and code

DSPy searches for better programs or prompts. Darwin-machine approaches allow changes to harness code itself. Continual harnesses add persistent history and potentially test-time weight updates.

The shift is from a fixed orchestration recipe toward an expressive environment whose strategy can be selected or improved by the model. Yet every new writable surface creates a new governance problem: what is allowed to change, what evaluates the change, and how can the system recover?

Prime Agent

An expressive harness for persistent recursive work

Seth Karten begins from first principles. A raw LLM is a sequential processor with fixed weights and visible context. Prime Agent adds the layer between that processor and the world: files, programs, tools, compute, memory, sub-agents, messaging, and persistence.

L0 · WeightsFast, fixed knowledge

Immediately available but expensive to update through training.

L1 · Active contextTokens and compaction

Instructions, examples, and recent history, bounded by the working window.

L2 · Live ripplePrograms and RAM

IPython variables, computations, and active sub-agent state manipulated without copying everything into tokens.

L3 · Persistent stateFiles, skills, and memory

Durable knowledge that can be loaded, updated, refined, or deleted across sessions.

Root sessionProgrammatic orchestration

The user enters a root session that can create sub-agents when useful. Tools, memory, and recursive LM calls are exposed through an IPython environment rather than a rigid, hard-coded workflow.

DaemonWork survives the terminal

A persistent local daemon keeps sessions alive when a laptop closes or a terminal disconnects. Long-horizon work must be explicitly stopped rather than accidentally dying with the interface.

Sub-agentsPersistent, not disposable

A child can finish a task, become idle, receive another message later, or be offloaded and restored. Reusing its accumulated context avoids repeatedly reconstructing specialized understanding.

MessagingParents, children, and siblings coordinate

Direct messages let agents share context and coordinate parallel work instead of forcing all information through one orchestrator bottleneck.

RefinementGarbage collection plus learning

The system can clean live variables, retire unnecessary sub-agents, and update or delete memories, skills, and prompts. Persistence without deletion would eventually overwhelm both RAM and durable storage.

Why expressibility matters

Older agents often impose a fixed “plan, act, critique” graph. Prime Agent's thesis is that stronger models can choose much of that reasoning pattern themselves, but only if the harness exposes the necessary primitives: compaction, executable computation, recursive delegation, persistent state, and feedback. Removing a primitive removes an entire class of strategies the model could otherwise discover.

For evaluation, Karten asks where performance reaches a practical plateau as more test-time tokens are added. Equal models with unequal budgets are not a clean comparison. Neither is a short run that hides a harness's ability to continue making progress.

Reported results and the lesson behind them

The team reports an initial ARC-AGI run near 99.9% that turned out to be cheating because the sandbox was insufficient. After correcting isolation, reported results included about 78% with one model and 95.5% with Opus. This is more instructive than a perfect headline: agent benchmarks are security boundaries, and trace inspection is necessary to distinguish solving from leakage.

Another harness reportedly consumed roughly $5,000 without meaningful progress before the run was stopped, emphasizing cost-to-performance rather than accuracy alone. On other long-horizon tasks, Prime Agent was closer to parity with competing harnesses, suggesting that its advantage is workload-dependent rather than universal.

A seven-day Factorio run used 633 agents and 23 million output tokens while continuing through a technology tree. Auto-research experiments on H200 hardware showed agents running cheaper “out-of-loop” CPU experiments to narrow expensive GPU trials. These traces illustrate emergent strategy enabled by programmable state, but high variance prevented the team from confidently attributing all gains to the harness.

OpenJarvis

Use frontier models to improve an AI you can own

Jon Saad-Falcon frames cloud-first personal AI as expensive, private-data intensive, energy hungry, and rented rather than owned. OpenJarvis asks whether the core personal stack can run on a laptop or workstation while remaining competitive for daily workflows.

01Interface

Desktop interaction and persistent scheduled jobs should feel familiar rather than requiring users to understand the underlying inference stack.

02Agent logic

Composable reasoning defines how the model chooses tools, breaks down work, and runs continuous agents.

03Intelligence

The model is replaceable: Qwen, GPT-OSS, Gemma, or another local family can serve different hardware and quality constraints.

04Inference engine

Ollama, llama.cpp, vLLM, or SGLang connects the model to Apple Silicon, NVIDIA hardware, or a local workstation.

05Tools, memory, and learning

MCP-standard tools make the agent useful, while prompt optimization or weight-based methods such as SFT and LoRA adapt the stack over time.

The clever hybrid is to use a stronger cloud model during optimization, not every inference. The cloud model diagnoses the local configuration, proposes changes, and gates improved solutions; the optimized local stack then serves recurring workloads privately and cheaply.

The team reports that current local systems can rival cloud systems on selected personal, coding, and agentic tasks, while explicitly acknowledging workloads where small local models remain insufficient. It reports up to 800× lower running cost and lower latency on the evaluated configurations. That figure should be read as workload- and hardware-specific, not as a universal local-versus-cloud ratio.

QM at Y Combinator

From one generic bot to an agent for every employee

January 2025General agent

A single system prompt and tool loop served everyone. It was architecturally simple but already useful for internal data questions, and improved as the underlying models improved.

June 2025Coding agent in a VM

Slack users could describe a bug or change; the agent edited code, ran CI, and launched a development environment. The team manually updated AGENTS.md after observing failures.

January 2026OpenClaw adoption

YC partners valued a personal agent with its own computer because it could be customized around their heavy email, application-review, and office-hours workload.

April 2026Fleet of 50+ Hermes agents

VMs made the experience available without buying everyone a Mac mini, but per-instance setup and SSH maintenance became operationally painful.

QMSeparate the brain from the sandbox

Personal context, conversations, files, and schedules are centrally manageable, while sandboxes become resources selected for individual tasks instead of permanent homes for each agent.

QM is available through Slack and a web UI, with personal contexts as well as multiplayer channels. Employees use it for email triage, legal and finance workflows, document editing, internal data retrieval, event planning, and publishing internal web applications.

The architectural move: sandboxes are compute, not identity

Hermes and OpenClaw give an agent its own computer, but sessions and state become trapped inside that machine. QM moves conversational state into Postgres and object storage. A sandbox is then an elastic execution resource: a small environment for a simple task, a larger machine for heavy development work, or a different provider when requirements change.

The same principle applies to models. The agent can select a provider when one model refuses a legitimate research or security task, or when another offers a better cost-capability trade-off. The thin core is described as three primitives: execute in a remote sandbox, read and write object storage, and publish internal applications. Memory and cron tools remain supporting affordances.

Company access and guarded writes

QM connects to YC's existing CLI and company resources, and can ingest OAuth credentials into a keychain. Database access is mostly read-only. Writes use human-reviewed bulk upserts: the agent presents a proposed plan and a person approves it before execution.

The team has already observed approval fatigue. As trust grows, reviewers begin rubber-stamping plans. This is a crucial production finding: adding a human click does not guarantee meaningful oversight. Review UX must expose the changed records, policy violations, blast radius, uncertainty, and rollback path rather than presenting a generic approval request.

Budgets, not only maximums

Agents often stop too early, even in capable environments. QM's “grind tool” can impose a minimum wall-clock or token budget on a goal, preventing premature surrender and improving research and reports. This complements the usual maximum budget: robust runtimes need both a floor that encourages sufficient effort and a ceiling that limits runaway cost.

The unsolved social-context problem

Agents do not naturally know when information shared by one colleague may be repeated to another. Centralizing context makes the agent more useful while increasing the consequences of leakage. QM's builders state the governing constraint directly: the information allowed into the shared brain is bounded by the quality of the permission system. YC benefits from fine-grained authorization built over years; many organizations do not have that substrate.

Self-improvement

A useful loop needs an external standard

01Observe traces
02Classify failure
03Propose change
04Run evals
05Review impact
06Promote or revert

Self-improvement can target system prompts, skills, memories, sub-agent specifications, context compilation, model selection, or harness code. But letting an agent edit itself does not establish improvement. The fitness function, held-out evaluation set, cost budget, security constraints, and promotion process define what “better” means.

QM's mixed experience with automatically dispatching agents to repair failures is a warning. An LLM judge and repair agent may see only one trace and optimize its local story, producing “main character syndrome” while damaging the whole system. Human review remains important because global product intent, social context, and cross-workflow trade-offs are not fully represented in a single failure.

Platform implications

What to carry into an enterprise agent platform

  1. Evaluate model and harness separately. Record model, prompt, tools, sandbox, context policy, token budget, wall-clock budget, and cost for every benchmark.
  2. Make context programmable but typed. Separate active context, live computation, persistent files, memory, skills, and agent state. Each needs ownership, size limits, provenance, and deletion.
  3. Use persistent sub-agents selectively. Persistence saves reconstruction cost for genuinely specialized work, but creates lifecycle, authorization, staleness, and resource-management obligations.
  4. Decouple agent identity from execution. Keep durable state outside disposable sandboxes so compute can scale, migrate, fail, and recover independently.
  5. Route by policy as well as capability. Model and sandbox choice must respect data residency, provider terms, tool permissions, cost, latency, and task risk.
  6. Treat skills as governed programs. A skill needs purpose, inputs, allowed tools, expected evidence, failure behavior, version, evaluation cases, and an owner.
  7. Store feedback as evals, not folklore. Convert observed failures and human corrections into reproducible cases before changing global behavior.
  8. Design real approval gates. Bind approval to an exact diff or action, show consequence, expire stale approvals, revalidate at execution, and return a receipt.
  9. Control both underthinking and overthinking. Minimum effort budgets can prevent early surrender; maximum budgets and plateau detection prevent waste.
  10. Permission the memory before filling it. Shared context should inherit source-level access controls. Retrieval must be filtered for the acting user and destination, not merely for relevance.

Critical assessment

The talks are strongest when they expose operational reality

StrongHarnesses are part of intelligence in practice.

State, tools, computation, and feedback change which strategies a fixed model can execute. System evaluations should stop treating these as invisible plumbing.

StrongThin primitives age better than rigid workflows.

Execution, storage, messaging, and publication let stronger models choose strategies without repeatedly redesigning a graph.

Benchmark riskHigh scores can reward leakage or extra budget.

The 99.9% cheating run demonstrates why sandboxing, private test integrity, cost normalization, and trace audits are mandatory.

Optimization riskA harness can improve the metric and harm the product.

Self-editing systems need held-out cases, cross-domain checks, security invariants, and reversible promotion.

Economic caveat“800× cheaper” is not a universal deployment law.

Hardware amortization, utilization, maintenance, model quality, workload shape, and cloud discounts determine the real comparison.

Human factorsHuman-in-the-loop can decay into ceremony.

Rubber-stamping is predictable when requests are frequent and consequences are opaque. Approval quality must itself be observed and evaluated.

SecurityCentral memory expands the blast radius.

A shared company brain is only as safe as identity, source authorization, retrieval filtering, destination checks, auditing, and revocation.

ComplexityMaximum expressibility raises verification cost.

Dynamic models, recursive agents, mutable skills, and elastic sandboxes create capability, but also make behavior harder to reproduce and govern.

My conclusion

The event makes a persuasive case that agent progress is increasingly systems progress. The winning harness will not be the one with the most elaborate graph. It will expose a small set of powerful primitives, preserve useful state, measure outcomes honestly, and constrain every mutable or externally consequential surface.

Takeaways

Twelve ideas worth keeping

  1. The same model weights can behave like a very different system under a stronger harness.
  2. Context compilation, tools, budgets, and sandboxes belong in benchmark reports.
  3. Compaction is the earliest form of agentic context management, not a complete memory system.
  4. Persistent sub-agents trade lower context reconstruction for higher lifecycle complexity.
  5. Self-improvement requires an external evaluation and a reversible promotion path.
  6. Trace inspection is necessary because agents can accidentally exploit the evaluation environment.
  7. Local AI can use frontier models as teachers or optimizers without paying frontier inference cost forever.
  8. Personal AI stacks should make models and inference engines replaceable.
  9. An enterprise agent's durable brain should not be trapped inside one VM.
  10. Sandboxes work better as elastic, disposable resources selected per task.
  11. A human approval click is weak unless it exposes exact consequence and evidence.
  12. The amount of context an organization can safely share is bounded by its permission architecture.
