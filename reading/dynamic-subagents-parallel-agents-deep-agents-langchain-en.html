The Short Version

Deep Agents already had subagents for context isolation. Dynamic subagents add programmatic orchestration: the main agent writes code, uses the code interpreter middleware, calls a task global, and fans out subagents in parallel. This makes big workflows more reliable because coverage, branching, retries, synthesis, and stop conditions move into code.

  • Subagents keep main-agent context clean by doing work in isolated context windows and returning compact results.
  • Dynamic subagents help when the task is too repetitive or large for turn-by-turn tool calling.
  • The workflow keyword steers the agent toward writing orchestration code instead of handling everything mentally.

Why Dynamic Subagents

The problem is not subagents. The problem is unreliable orchestration at scale

Ordinary subagents already solve one big problem: context isolation. Each subagent receives a focused task, works in its own context window, and returns results to the main agent. The gap appears when the main agent must call the subagent tool hundreds of times, keep track of coverage, merge results, retry failures, and decide when it is done.

Plain Tool Calling

The main agent repeatedly decides which subagent to call next. For a few calls this works, but for large jobs it can skip items or stop early.

Dynamic Subagents

The main agent writes orchestration code that loops over items, spawns subagents, waits for results, and merges them deterministically.

Reliability Gain

Completeness stops depending on prompt luck. A loop can cover all pages, files, tickets, candidates, or services.

The key idea: move orchestration out of the agent's head and into code whenever code is the clearer control surface.

Mechanism

The code interpreter middleware gives the agent a programmable subagent API

LangChain's code interpreter middleware provides a lightweight in-memory sandbox and exposes an eval tool. The agent writes a code block, the runtime executes it, and only the final result returns to the main context. For dynamic subagents, the important addition is the task global, which is the programmatic version of the Deep Agents task tool.

Steering

The workflow keyword tells the agent to write orchestration code

Once the middleware is attached, the agent can use dynamic subagents, but it may not always choose that path. In Decode, LangChain uses the workflow keyword as a steering signal. A request like "review every file in this PR" may or may not fan out, but "run workflow to review every file in this PR" explicitly asks for code-driven orchestration.

Plain request Workflow request Expected behavior
Review the utility code. Run a workflow to review every file in the utility code. Fan out one or more reviewers across files and synthesize a final report.
Find security issues. Run a workflow to find security issues and independently verify each finding. Generate candidates, send them to verifier subagents, and report confirmed issues only.
Suggest a refactor. Run a workflow to generate several refactor designs and pick the strongest one. Generate multiple candidates, score or compare them, then recommend a winner.
Six Patterns

Dynamic subagents turn common agent workflows into reusable orchestration shapes

The video walks through six patterns, originally shaped by Anthropic's dynamic workflow framing and demonstrated through LangSmith traces. Each pattern is triggered by the task shape and by how the workflow request is phrased.

1. Classify and Act

Use when mixed inputs need different handling. The agent classifies items, groups them, and sends each group to the right subagent type.

Run a workflow to classify each support ticket and handle each type the right way.

2. Fan Out and Synthesize

Use when every item needs the same operation and the user wants one combined output. The agent covers all files or documents in parallel.

Review every file and give me one prioritized summary.

3. Adversarial Verification

Use for high-stakes precision. One pass finds candidate issues, independent verifier subagents check them, and only confirmed findings are reported.

Find issues, independently verify each one, and report only confirmed findings.

4. Generate and Filter

Use for open-ended quality. Several subagents produce candidate designs or approaches, then the agent scores and keeps the strongest one.

Generate several redesigns, score them, and recommend the best with rationale.

5. Tournament

Use when "best" is subjective. Candidate variants compete head to head and judge subagents advance winners until one remains.

Produce several rewrites and compare them head to head until one winner stands out.

6. Loop Until Done

Use for exhaustiveness. The agent runs passes, deduplicates what it already found, and keeps going until a pass finds nothing new.

Find all dead code and do not stop until a full pass turns up nothing new.
Schemas and Traces

Typed outputs and traces are what make these workflows inspectable

A repeated detail in the demos is dynamic response schemas. When the main agent knows that a subagent result contains fields like severity, evidence, confirmed, reason, score, or file path, it can write code that branches and filters safely. Platform Takeaways

What this means for your agentic AI platform

This video maps very directly to your Master Agent, Sub-Agent, Skill, Tool MCP, and Flow Markdown design. A BA-facing platform should let users choose workflow shapes, not force them to hand-write every orchestration detail.

  • Make dynamic subagent patterns first-class. Let BAs choose Classify and Act, Fan Out and Synthesize, Verify, Generate and Filter, Tournament, or Loop Until Done.
  • Compile Flow Markdown into orchestration code. A flow should produce loops, branches, retries, parallel fan-out, schema contracts, and stop conditions.
  • Keep Master Agent context clean. The Master Agent should own goal, plan, state, and synthesis while Sub-Agents handle isolated heavy work.
  • Define subagent types like roles, not just prompts. Each Sub-Agent type needs scope, input schema, output schema, allowed tools, evaluation rule, and trace labels.
  • Use typed response schemas everywhere. Business workflows need structured outputs so the platform can branch, verify, deduplicate, rank, and audit.
  • Add explicit steering language. Your UI can expose "Run as workflow" or "Use parallel subagents" instead of relying on hidden prompt keywords.
  • Show a dynamic subagents view. Users should see each phase, running subagents, task descriptions, durations, status, and result summaries.
  • Separate candidate generation from verification. High-risk business processes should use independent verifier subagents before actions are accepted.
  • Treat completion as a policy. "Every file", "confirmed only", "winner selected", and "no new findings" are different stop rules that should be configurable.
BA Templates

Reusable templates for a BA-facing dynamic subagent builder

The most useful product translation is a template library. Instead of asking a BA to understand code interpreter middleware, the platform can expose workflow templates that compile into safe orchestration code and traceable subagent calls.
