The Short Version

Karpathy argues that LLMs are becoming a new kind of computer. Software 1.0 is explicit code. Software 2.0 is learned weights. Software 3.0 is programming through prompts, context, examples, tools, and agent workflows. Vibe coding raises the floor, but agentic engineering preserves the quality bar while using fallible but powerful agents.

  • The biggest opportunities are not only faster code, but new information-processing products that could not exist before.
  • AI automates fastest where outputs can be verified, rewarded, tested, or simulated.
  • Humans still own taste, spec, architecture, judgment, and understanding.

Software 3.0

The programming interface is moving from code to context

Karpathy frames the shift as three eras. In Software 1.0, humans write explicit rules. In Software 2.0, humans curate data and objectives to train neural networks. In Software 3.0, the LLM is an interpreter over context, and the context window becomes the main lever.

Software 1.0 Write code over structured data. The program is explicit and deterministic.
Software 2.0 Arrange datasets, objectives, and architectures. The program lives in learned weights.
Software 3.0 Write prompts, specs, examples, and tool instructions. The LLM interprets context.
Agentic Runtime The model uses tools, sees the environment, debugs, and takes action in a loop.

The practical question becomes: what is the right piece of text, context, image, file, or tool contract to give the agent?

New Products

The mistake is treating AI as only a speed-up for existing software

Karpathy's menu example shows the difference. One approach builds a traditional app that uploads a menu, OCRs items, generates food images, and renders a UI. The Software 3.0 version is more direct: give the menu image to a model and ask it to transform the image itself.

Old Mindset

Build an app around the task

Classical software decomposes the work into OCR, parsing, image generation, database, frontend, and deployment pieces.

New Mindset

Ask the model to transform the artifact

For some tasks, the prompt and source artifact can replace large parts of the application pipeline.

Opportunity

Recompile information

LLMs can turn documents into wikis, notes into knowledge bases, and raw facts into new projections that were not practical before.

Engineering Discipline

Vibe coding raises the floor; agentic engineering protects the quality bar

Karpathy separates casual AI-assisted creation from professional engineering. Vibe coding lets many more people build things. Agentic engineering is about using powerful, spiky, stochastic agents without introducing security problems, brittle architecture, or quality regressions.

Vibe Coding

Fast creation

The model can produce larger chunks of working code, so individuals can explore, prototype, and ship side projects quickly.

Agentic Engineering

Fast creation with discipline

The human team still owns security, architecture, correctness, tests, deployment, observability, and maintainability.

  • Agentic engineers invest in their setup, tools, context, workflows, and evaluation process.
  • Hiring for this skill should look less like puzzles and more like large project execution under quality and security constraints.
  • The ceiling may be much higher than the old "10x engineer" idea, but only for people who can direct agents well.
  • The professional bar does not disappear. It moves into specs, review, constraints, tests, and judgment.
Human Role

The human role shifts toward taste, spec, design, and understanding

Karpathy says agents are like capable interns: strong recall, useful implementation ability, but still prone to strange design mistakes. His example is a payment flow where an agent matched Stripe and Google accounts by email instead of using a persistent user ID.

Fundamentals

Understanding

Oversight

Stay in the loop

Education

Agent-Native World

Infrastructure, docs, and workflows need to be written for agents first

Karpathy argues that much of today's digital world is still written for humans. Docs tell humans which buttons to click, URLs to open, and settings to configure. In an agentic world, the better artifact is often a copy-pasteable instruction, a tool contract, or a machine-legible interface the agent can execute.

Docs

From human guide to agent instruction

Instead of "go here, click this," provide the exact context, command, or API path an agent can use.

Infrastructure

Deployment should be agent-operable

The hard part of side projects was not just code, but DNS, settings, services, deployment, and integration.

Interfaces

Think sensors and actuators

Agent-native systems expose what agents can observe and what they are allowed to change.

Organizations

People and companies get agent representations

Karpathy imagines personal and organizational agents negotiating details like meetings and coordination.

Data

Make structures legible to LLMs

Systems should expose state, logs, and business objects in forms that models can reliably read and act on.

Control

Permissions become product design

Agents with real permissions need clear boundaries, auditability, rollback, and human approval paths.

Platform Takeaways

What this means for your agentic AI platform

This conversation is almost a product strategy memo for your BA-facing multi-agent platform. The big lesson: let BAs describe verifiable business behavior, then turn that behavior into specs, evals, tools, memory, permissions, traces, and agent-native instructions.

  • Make verifiability a first-class field. Every business flow should declare how success is checked: exact output, policy rule, tool state, user confirmation, judge score, simulator, or human approval.
  • Separate vibe prototyping from governed agentic engineering. The platform can allow fast drafts, but promotion to production should require evals, trace evidence, permission review, and release gates.
  • Design Flow Markdown as Software 3.0 code. A flow is not documentation only. It is the program-like context that tells agents objectives, constraints, tools, memory checkpoints, and escalation rules.
  • Represent each Skill as an agent-native artifact. Cognitive skills should define reasoning patterns and scoring. Actionable skills should define tool contracts, schemas, side effects, retries, permissions, and audit logs.
  • Build a verifiable environment library. Give BA users templates for policy checks, document extraction checks, claims checks, approval checks, customer-service checks, and compliance checks.
  • Expose sensors and actuators. Sensors are what an agent can read: documents, CRM records, logs, policies, tickets. Actuators are what it can change: create case, send email, update status, request approval.
  • Keep human understanding in the loop. BA users should own intent, business invariants, examples, exception logic, and what "good" means. The system can automate implementation and testing around that.
  • Test for jaggedness. Do not trust broad model quality. Test exact business circuits, especially edge cases where common sense, identity, money, compliance, or user permissions matter.
  • Make docs copy-pasteable to agents. Replace human-only SOP pages with agent-readable instructions, structured examples, tool specs, expected outputs, and failure handling.
  • Promote knowledge bases as understanding tools. Summaries, wikis, graph views, and alternative projections help humans direct agents because they compress information into forms humans can actually understand.
