The problem

What was missing before this work

Autoregressive attention stores keys and values for every retained token in every layer. Memory grows linearly with context, batch size, layers, KV heads, and precision, often limiting concurrency before model weights do.

Optimization can alter architecture, allocation, precision, token retention, or storage tier. This guide focuses on three papers that compress the existing cache.

Core idea

The paper in one idea

H2O treats a small set of attention heavy hitters as important and combines them with recent tokens. KIVI uses asymmetric 2-bit quantization, exploiting different outlier patterns in keys and values. SnapKV observes attention near the prompt boundary to select positions likely to matter during generation.

The methods are complementary in principle, but their errors can compound. The correct design depends on whether the workload needs exact retrieval, broad summarization, long generation, or high concurrency.

KV bytes ≈ 2 × layers × retained tokens × KV heads × head dimension × bytes/value.

Mechanism

How the method works

H2O scores historical tokens by accumulated attention and evicts low-value entries while preserving recency. KIVI quantizes keys per channel and values per token, retaining a small full-precision residual window. SnapKV pools attention votes across heads and keeps selected prompt clusters.

All methods require kernels and cache metadata that match their representation. Quality evaluation must target position, domain, and generation length.

Technical deep dive

The machinery that matters

The cache equation shows independent multipliers. GQA reduces KV heads; low-bit methods reduce bytes per value; eviction/selection reduces retained tokens; paging reduces allocation waste; offload changes memory tier.

Attention importance is layer- and head-dependent. Quantization outliers differ between keys and values. A method that preserves perplexity may still fail exact needle retrieval.

Evidence

What the experiments established

H2O reported strong generation quality with a small heavy-hitter cache. KIVI reported near-lossless quality with a 2.6-times peak-memory reduction and higher throughput in tested systems. SnapKV reported large prompt-cache reductions with limited benchmark loss.

The papers use different models, tasks, baselines, and budgets; headline ratios should not be compared as one leaderboard.

Why it mattered

How it changed the field

KV optimization became essential as context windows and concurrent serving grew. It expanded inference configuration beyond weight quantization into dynamic state management.

The field now combines architectural sharing, quantization, eviction, prefix caching, paging, and tiered storage.

Engineering use

What an AI engineer should do with it

Start from the cache equation and profile prefill, decode, and transfer separately. Pick a method only after identifying which multiplier or memory tier causes the bottleneck.

Build adversarial long-context evals: exact retrieval at every position, repeated entities, code dependencies, tool history, and long generation. Log which tokens are evicted or quantized.

Limits and later corrections

Where the result stops

Eviction and selection can permanently discard evidence. Quantization can perturb attention scores, and custom kernels may erase theoretical gains. Combining lossy methods can fail nonlinearly.

No method guarantees universal long-context quality. Cache policy may need per-request risk levels, with exact retention for regulated or high-value tasks.

Takeaways

What to remember

  • KV memory has several independent multipliers.
  • H2O retains heavy hitters plus recent tokens.
  • KIVI quantizes keys and values asymmetrically.
  • SnapKV selects prompt positions from attention observations.
  • Memory savings and semantic loss must be measured together.
  • High-risk tasks may require an exact-cache path.
