The problem

What was missing before this work

LLM servers reserve contiguous KV-cache memory for uncertain maximum sequence lengths. Variable prompts and outputs create internal waste, external fragmentation, and expensive reallocation.

Poor memory utilization reduces batch size and throughput even when compute is available. Sharing prefixes or beam-search cache is also awkward with contiguous buffers.

Core idea

The paper in one idea

Divide each request’s KV cache into fixed-size logical blocks and map them to physical GPU blocks through a table, analogous to operating-system virtual memory pages.

PagedAttention kernels follow the mapping while continuous batching admits, pauses, and completes requests at token boundaries. Copy-on-write enables safe sharing.

Logical KV blocks map through a block table to non-contiguous physical GPU blocks.

Mechanism

How the method works

Allocate physical blocks only as tokens fill logical blocks. Store mappings per sequence. During attention, fetch K/V through the table. Reclaim blocks immediately when a request ends.

The scheduler mixes requests with different lengths and can swap or recompute state under pressure instead of reserving worst-case contiguous regions.

Technical deep dive

The machinery that matters

Only the final block of a sequence has internal waste, bounded by block size. Non-contiguous storage requires a custom attention kernel and metadata lookup but avoids large memory copies.

Block size trades metadata and kernel efficiency against waste. Prefix sharing uses reference counts and copy-on-write when sequences diverge.

Evidence

What the experiments established

The vLLM paper reported two-to-four-times throughput improvements over tested FasterTransformer and Orca-style systems at comparable latency, with larger gains for long and variable sequences.

Serving results are workload distributions, not model-only constants. Modern baselines and kernels have evolved, so current systems require fresh benchmarking.

Why it mattered

How it changed the field

PagedAttention made KV memory management a central serving abstraction and vLLM became a widely used open inference engine.

It enabled richer schedulers, prefix caching, distributed serving, and standardized OpenAI-compatible model endpoints.

Engineering use

What an AI engineer should do with it

Benchmark time to first token, inter-token latency, throughput, queue delay, and memory under the real prompt/output distribution. Average sequence length is insufficient.

Tune block size and scheduler limits together. Add admission control so a few very long requests cannot evict or starve interactive traffic.

Limits and later corrections

Where the result stops

Paging does not shrink the logical KV cache; it allocates it more efficiently. Extremely long contexts still consume large memory, and block lookup adds kernel complexity.

Throughput optimization can harm tail latency without service-level objectives. Swap or recomputation policies introduce their own latency cliffs.

Connections

Where this paper sits in the learning path

MQA/GQA reduce cache bytes per token, while PagedAttention reduces allocation waste across requests. KV compression reduces precision or retained tokens; these methods can be combined.

Takeaways

What to remember

  • Contiguous KV reservation wastes accelerator memory.
  • Logical blocks decouple sequence growth from physical placement.
  • Continuous batching improves utilization at token boundaries.
  • Copy-on-write supports shared prefixes safely.
  • Paging manages but does not eliminate KV growth.
  • Serving quality requires latency and throughput together.
