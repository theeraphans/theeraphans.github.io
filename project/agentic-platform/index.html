Agentic AI Platform

The storyArchitectureTechnical decisions

A reusable foundation for agents that need to do more than answer a question.

The problem

Each workflow needs routing, context, tools, and controls for consequential actions. Rebuilding these capabilities for every agent makes evaluation and maintenance harder.

My contribution

I built a local toolkit for defining agents and their tasks, connecting them to business tools, and checking their answers against example cases. A separate review process lets a person inspect suggested changes before promoting an agent version.

Current stage: local implementation with services for agent execution, chat channels, business tools, and evaluation, alongside test suites. I inspected the source for this update; this page does not claim a production deployment or a completed live end-to-end validation.

Technical decisions & boundaries

  1. Runtime boundary

    The core creates and runs capabilities. Routers and loaders prepare state before graph execution; graph nodes consume state and return patches.

  2. Tool boundary

    MCP servers expose business capabilities. The diagram groups individual tools rather than implying every tool is called on every request.

  3. Evaluation boundary

    Evaluation runs beside execution. Curated cases and recorded tool evidence help distinguish a bad answer from an incorrect action.

  4. Version contract

    The core and evaluation service share the version under test. Suggested changes require review before creating or promoting a later version.
